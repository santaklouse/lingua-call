# Задержки: измерение и настройка

[English](PERF.md) | **Русский**

Главная фича должна ощущаться живой (PLAN.md D23). Здесь — как измерять пайплайн
и что настраивать.

## Цели (D23)

| Этап | Цель (p50) | Цель (p90) |
|---|---|---|
| ASR final после конца фразы | ≤ 700 мс | ≤ 1200 мс |
| MT (финальный сегмент) | ≤ 150 мс | ≤ 300 мс |
| Старт TTS | ≤ 300 мс | ≤ 600 мс |
| **Итого (конец фразы → озвучка)** | **≤ 1.5 с** | **≤ 2.5 с** |

## Как измерять живое демо

1. Открой `bun run dev` (или HTTPS-деплой) в Chrome/Edge → lobby →
   **Live translation demo**.
2. Повтори одну короткую фразу 10+ раз (например «Привет, как дела?»), затем
   несколько длинных.
3. Таблица **Latency (ms)** показывает `last / p50 / p90 / samples` для
   `ASR`, `MT`, `TTS playback`, `End-to-end`.
4. Нажми **Copy metrics** — в буфер скопируется JSON с языковой парой, браузером
   и сводкой задержек. Приложи его к задаче/чату.
5. Повтори со «прогретым» prefetch (со второй фразы) и отдельно зафиксируй первую
   фразу — там загрузка модели/голосов.

В звонке виджет **Debug console** логирует состояния соединения, отправку/приём
субтитров и старт/конец озвучки; кнопка **Copy** копирует весь лог звонка.

## Что влияет на задержку и что крутить

| Параметр | Где | Эффект |
|---|---|---|
| Warmup движков (переводчик/голоса) | `TranslationPipeline.start()` | убирает загрузку модели на первой фразе |
| Prefetch стабильного partial (450 мс) | `pipeline.ts` (`PREFETCH_STABILITY_MS`) | прячет MT за финализацией ASR |
| Скорость TTS (1.05) | `web-speech-tts.ts` | чуть быстрее речь, меньше очередь |
| Single-slot очередь озвучки | `pipeline.ts` / экран звонка | выбрасывает устаревшие фразы вместо отставания |
| Длина предложений | сегментация ASR/MT | короче — раньше старт, но хуже перевод |
| Браузер/сеть | Web Speech может ходить в облако вендора | долгосрочное решение — локальные WASM (P5A/P5T) |
